The RTL design method: datapath and control unit

Large systems are split into a datapath (registers, counters, arithmetic, multiplexers: where data live and are transformed) and a control unit (a state machine deciding which operation happens in each cycle); the controller is first written with symbolic micro-operations (, ) and conditions, the datapath is built to execute them, then each micro-operation and condition is encoded as control and status signals.

Method

Why: an 8-bit register alone has 256 states — too many to draw — but its value rarely affects the flow of operations. Separate concerns:

  • Datapath: data inputs and outputs, registers and counters, arithmetic/logic units, comparators, multiplexers and buses. Receives control signals (enables, loads, mux selects, operation codes), returns status signals (terminal count, carry, overflow, comparator outputs).
  • Control unit: an FSM with the control inputs and outputs of the system (buttons, lamps), producing the control signals from the state and the status signals.

Both are synchronous on the same clock; the split is conceptual (deciding vs executing), not "combinational vs sequential". Steps:

  1. specification; 2. primary inputs and outputs, data and control; 3. data registers; 4. control FSM with symbolic register transfers and conditions; 5. datapath schematic implementing them; 6. encoding of micro-operations into control signals (default 0, list only those at 1) and of conditions into status signals; 7. detailed design of both; 8. verification (timing diagrams, simulation). Steps 4–5 are usually iterated together.

Timing rule: a load commanded in state is visible in the register only in the next cycle (next state); a combinational result (comparator) is valid in the same cycle, after its delay, and must settle before the edge — glitches on it are harmless because the FSM samples at the edge.

Stopwatch 00.00–99.99 s, buttons START (reset and run), STOP, CSS (compare and store shortest), RESET (clear best time). Intuition

The datapath is the orchestra, the controller the conductor: it never plays a note, it only says who plays when.

Pitfall

Testing in a state the value just loaded in that same state reads the old value. Merging states to save flip-flops can silently change the behaviour (e.g. a waiting state that now also reacts to CSS before any time has been measured) — re-check the specification after every optimization.
