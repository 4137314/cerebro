Immutable objects

An immutable object cannot change after construction: all fields final and private, no setters, the class final, and defensive copies of mutable inputs and outputs; such objects are thread-safe without locks, safe as map keys and freely shareable — String, the wrappers and Java records are the standard examples.

Definition

Recipe:

  1. declare the class final (no subclass can add mutable state);
  2. make every field private final;
  3. provide no method that modifies the state ("wither" methods return a new object instead);
  4. copy mutable arguments in the constructor and mutable fields in getters (defensive copies).

Java 16 record Point(int x, int y) {} generates such a class with constructor, accessors, equals, hashCode and toString.

Example

Intuition

If nothing can change, nothing needs protecting: no race conditions, no hidden aliasing, no stale hash buckets.

Pitfall

final on a reference does not make the referenced object immutable: a final List can still be modified. Building long strings with s + x= in a loop creates a new String each time (); use StringBuilder.
