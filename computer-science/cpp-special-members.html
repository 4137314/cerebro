Special member functions and RAII

Even an empty C++ class has a default constructor, a copy constructor, a copy assignment and a destructor generated by the compiler (plus move operations since C++11); they copy and destroy member by member, and = default / = delete request or forbid them explicitly.

Definition

For class A {}; the compiler provides

and, from C++11, A(A&&) and A& operator=(A&&) (see move semantics). The generated versions work member by member: copy each member, destroy each member.

  • Declaring any constructor with parameters removes the implicit default constructor: A a; stops compiling unless A() = default; is added back.
  • = delete forbids an operation: A(const A&) = delete; makes A non-copyable.
  • The copy constructor is called for initialisation (A b(a), A b = a, pass and return by value); operator= for assignment to an existing object.

RAII

Resource Acquisition Is Initialisation: the constructor acquires a resource (memory, file, lock), the destructor releases it. Since destructors run automatically when an object goes out of scope, also during exception unwinding, the resource can never leak. std::string, std::vector, std::unique_ptr, std::lock_guard are all RAII classes.

Worked example

Intuition

The compiler writes the boring members for you, and they are right as long as every member manages itself. The moment a member is a raw owning pointer, they are wrong.

Pitfall

operator= returns A& (*this) so that a = b = c works as a = (b = c), and must survive self-assignment a = a.
