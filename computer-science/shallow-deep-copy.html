Shallow and deep copy, rule of three

The generated copy copies pointers, not what they point to, so two objects end up sharing (and both deleting) one heap object; a class that owns memory must define destructor, copy constructor and copy assignment together.

Statement

Shallow copy: copy the members' values; for a pointer member, the address. Deep copy: copy the pointed object too, so the copy owns its own.

Rule of three: if a class needs a user-defined destructor, copy constructor or copy assignment, it needs all three. (Rule of five with the two move operations.)

Derivation

Take class A { int i; B* pb; }; with pb owning a heap B. The generated copy constructor copies pb: after A a2(a); both point to one B. Changing a2's B changes a's; when both die, ~A deletes the same B twice. Defining the copy to allocate a new B restores one B per A.

Intuition

Copying a house key is not copying the house. If each object is supposed to have its own house, the copy has to build one.

Pitfall

Java has the same distinction: assignment copies references, clone() is shallow by default, and a deep copy must be written by hand.
