Template specialization, SFINAE and concepts

A template can be given a separate definition for chosen arguments: full (explicit) specialization fixes all of them, partial specialization (class templates only) fixes a pattern such as "any pointer"; overload resolution silently discards templates whose substitution fails (SFINAE), which C++20 concepts replace with named, readable constraints.

Construction

The compiler picks the most specialised matching definition. The standard library specialises std::vector<bool> to pack bits, and std::hash<T> is specialised by users to put their types in unordered containers.

SFINAE and concepts

"Substitution failure is not an error": if substituting the arguments into a template's signature produces an invalid type, that candidate is dropped, not reported.

A call half2(2.5) now fails with "constraint std::integral<double> not satisfied" instead of pages of instantiation errors.

Intuition

Specialisation is "same name, different recipe for this case"; concepts are "this recipe only for ingredients that have these properties".

Pitfall

Function templates cannot be partially specialised; use overloading instead. And an explicit specialisation must be declared before the first use that would instantiate the primary template, or the program is ill-formed.
