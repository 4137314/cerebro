C++ templates

template <typename T> introduces a function or class written for an unknown type; each use with concrete arguments instantiates a separate copy at compile time, arguments of function templates are deduced from the call, and specialisations replace the generic code for chosen arguments.

Construction

  • Instantiation: max(2, 3) creates max<int>; Pair<string,int> creates a class. Uninstantiated members are not even compiled (laziness).
  • Deduction: the compiler infers T from the arguments; max(3, 2.3) fails because T cannot be both int and double; max<double>(3, 2.3) or a second parameter template <class T1, class T2> fixes it.
  • Specialisation: template <> struct factorial<0> { ... }; gives a separate definition for one argument; the library specialises vector<bool>.
  • Non-type parameters: template <unsigned N> class bitset;, values known at compile time.

Where to put the code

A template is a recipe, not code: its full definition must be visible where it is instantiated, so templates live entirely in headers (including the definitions of the member functions).

Intuition

A template is a macro with types and rules: the compiler stamps out a fresh, fully typed copy for every set of arguments you use.

Pitfall

Errors appear at instantiation, deep in the template, with long messages; C++20 concepts state the requirements up front and give short errors.
