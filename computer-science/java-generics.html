Java generics and type erasure

Since Java 5 classes, interfaces and methods can take type parameters (class Stack<T>, <T> T max(...)) checked at compile time; the compiler then erases them to their bounds (usually Object) and inserts casts, so one class serves all instantiations and no type information remains at run time.

Construction

Type erasure

After checking, the compiler replaces each type parameter with its bound (Object, or Comparable for T extends Comparable<T>) and inserts casts at the uses: String x = (String) s.pop();. Consequences:

  • one .class per generic class, no run-time overhead, compatibility with pre-generic code (raw types, with warnings);
  • type parameters cannot be primitive (Stack<int> is illegal; use Stack<Integer>);
  • no new T(), no new T[n], no x instanceof Stack<String>, no static field of type T.

Intuition

Generics are a compile-time contract. The compiler checks you keep it and then throws the contract away, leaving the casts it proved safe.

Pitfall

Raw types (Stack s = new Stack();) switch the checks off and turn type errors into [[id:casting-instanceof][ClassCastException]] far from their cause. Always use the parameterised form.
