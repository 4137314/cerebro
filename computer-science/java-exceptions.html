Exceptions in Java: checked, unchecked, finally

Java exceptions are objects of subclasses of Throwable; checked exceptions (subclasses of Exception but not of RuntimeException) must be caught or declared with throws, unchecked ones need not; finally and try-with-resources guarantee clean-up.

Definition

The catch-or-declare rule: a method in which a checked exception can arise must either handle it with try/catch or list it in its signature, void load() throws IOException. So callers know from the interface which failures to expect. Run-time exceptions signal programming errors and are exempt.

Example

finally runs whether the block completes, throws or returns: the place for releasing resources, without duplicating code in every catch. Try-with-resources does it automatically for any AutoCloseable.

Intuition

Checked exceptions are part of the contract: the signature tells you what can go wrong that is not your fault.

Pitfall

catch (Exception e) {} swallows every error, including bugs; catch the narrowest type you can handle. A catch of a superclass placed before its subclass makes the second unreachable: compile error.
