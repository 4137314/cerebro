The Java platform

javac compiles .java sources to bytecode in .class files; the Java Virtual Machine loads, verifies and runs that bytecode (interpreting and JIT-compiling it) on any operating system, with a garbage-collected heap and a large standard library.

Model

  • Source: one public class per file Name.java; classes grouped in packages.
  • Compilation: javac Name.java produces Name.class, containing bytecode for a stack-based virtual machine, not machine code.
  • Execution: java Name starts a JVM, which loads the classes on demand, verifies the bytecode, interprets it and compiles the hot parts to native code (just-in-time). Entry point: public static void main(String[] args).
  • Platform: JDK (compiler and tools) ⊃ JRE (JVM and libraries). The reference implementation is OpenJDK.

Java is C-like in syntax but removes pointers with arithmetic and manual memory, and adds classes, inheritance, polymorphism and a standard library for I/O, threads, collections, exceptions and networking.

Picture

One compiled artefact, many machines.

History

Born at Sun in the early 1990s for consumer electronics, re-targeted in 1994 to the Web (moving code, not only data, between client and server), general purpose from 1996, acquired by Oracle with Sun in 2010. Android uses Java (and Kotlin) on its own, incompatible, virtual machine.

Intuition

C++ compiles for the machine; Java compiles for an imaginary machine and ships a program that emulates it everywhere.

Pitfall

"Compiles" is not "runs": classes are loaded at run time, so a missing class or a version mismatch shows up as NoClassDefFoundError or UnsupportedClassVersionError only when the code is executed.
