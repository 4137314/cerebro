Value categories and rvalue references

An lvalue names an object with an address that persists (it can stand left of ); an rvalue is a temporary about to die (=3, a + b, a returned value); C++11's T&& binds only to rvalues, so a function can tell "a copy is needed" from "the source can be plundered".

Definition

Every expression has a type and, orthogonally, a value category.

  • lvalue: designates a persistent object; it can appear on the left of an assignment: x, *p, v[i].
  • rvalue: a temporary value: literals, x + y, the result of a function returning by value.

C++11 refines them into lvalue, xvalue ("expiring", e.g. std::move(x)) and prvalue; glvalue = lvalue or xvalue, rvalue = xvalue or prvalue.

Reference binding:

Temporaries

A operator+(const A&, const A&) builds a local A temp, returns it by value: the caller receives a temporary that will be destroyed at the end of the full expression. Copying from it is wasteful, because nobody will look at it again.

Intuition

An lvalue has a name and a future; an rvalue has neither. Overloading on && lets code steal from things without a future.

Pitfall

A named rvalue reference is itself an lvalue: inside A(A&& a), a has a name, so passing it on requires std::move(a) again.
