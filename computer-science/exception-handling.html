Exceptions

An exception is an object describing an abnormal event; throw interrupts the normal flow, the run time unwinds the stack of calls until a try block with a matching catch is found, separating error handling from the normal code and letting the caller, not the callee, decide what to do.

Method

Traditional error handling has known limits: terminating in the callee (a decision that belongs to the caller), conventional return values (confusing when an error has the type of a result, impossible for constructors, no information about the cause), a global error handler (centralised, unreadable). Exceptions:

  • separate the handling from the application code;
  • propagate errors in a controlled way along the dynamic chain of calls;
  • group or distinguish errors through a class hierarchy (catching a base class catches all its subclasses).

Mechanism

When an exception is thrown, the current block stops; the frames of the call stack are popped one by one (unwinding), running the destructors of their local objects in C++, until a matching catch is found. If none exists, the program terminates.

Picture

Intuition

An exception is a return that skips every caller that does not know what to do with the problem, landing on the first one that does.

Pitfall

Exceptions are for exceptional events, not for normal control flow. In C++, code that acquires resources without RAII leaks them when an exception skips the release.
