Wrapper classes and autoboxing

Every primitive type has an immutable wrapper class (Integer, Double, Boolean, …) so that numbers can live where objects are required, such as in collections; since Java 5 the compiler converts between them automatically (autoboxing and unboxing).

Wrappers are immutable objects with utility methods (Integer.parseInt, Integer.MAX_VALUE, Double.compare). The compiler inserts the conversions: Integer x = 5; becomes Integer.valueOf(5) (boxing), int y = x; becomes x.intValue() (unboxing).

Example

Intuition

Generics and collections only speak objects; wrappers are the envelopes numbers travel in, and autoboxing seals and opens them for you.

Pitfall

== compares references: Integer a = 1000, b = 1000; a = b= is false (only values in are cached), and unboxing a null Integer throws NullPointerException.
