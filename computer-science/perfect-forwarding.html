Forwarding references and perfect forwarding

In a template, a parameter T&& with deduced T binds to both lvalues and rvalues (a forwarding reference): reference collapsing makes T an lvalue reference for lvalues; std::forward<T>(x) then passes the argument on with its original value category, which is how emplace_back and make_unique build objects in place without extra copies.

Construction

Reference collapsing: & &, & &&, && & collapse to &; only && && gives &&. For

  • called with an lvalue of type A: =A&=, parameter A& && → A&; std::forward<A&>(x) is an lvalue: target copies;
  • called with an rvalue: =A=, parameter A&&; std::forward<A>(x) is an rvalue: target moves.

Example

Intuition

A forwarding wrapper should be invisible: whatever the caller passed — something to copy or something to steal from — the final target should see exactly that.

Pitfall

T&& is a forwarding reference only when T is deduced for that very function; void f(std::vector<T>&&) or a member void g(T&&) of a class template is a plain rvalue reference. Forwarding the same argument twice may move from it twice.
