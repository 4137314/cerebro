Worked design: a vending-machine controller

A typical design problem — decode 3-bit serial commands (start bit + 2 bits), drive a credit accumulator with , dispense when the credit is at least 30 and return change one coin per cycle — is solved with a 9-state machine whose decoding states are a tree on the serial bits, whose fixed operations are chains of Moore states and whose change loop is a single state with outputs conditioned on the status signal .

Example

Specification. Drink 30 cents; coins of 10 and 20; change and refunds only in 10-cent coins. Commands on a serial line (synchronous, idle 0), 3 bits, first the start bit 1: 100 coin 10, 101 coin 20, 110 dispense, 111 refund. Datapath: accumulator credit with synchronous , (adding 20 = two cycles of ); comparators and (combinational, negligible delay). Outputs: one cycle to dispense, one coin per cycle. At the end the credit must be 0. States (Moore outputs in brackets, default 0):

  • IDLE: busy-wait for the start bit; START.
  • START: read bit 2; COIN, REQ.
  • COIN []: read bit 3; IDLE (10 added), ADD2.
  • ADD2 []: second 10 of a 20 coin; → IDLE.
  • REQ: read bit 3; CHG (refund); D1; IDLE (not enough credit: keep it, wait).
  • D1 [] → D2 [] → D3 [] → CHG: dispense and take 30.
  • CHG: if : conditional outputs , stay; else → IDLE.

The change loop cannot go below 0: in CHG looks at the value of this cycle, and the decrement appears in the next one, so with credit 10 the machine pays one coin and sees 0 in the following cycle. The coin decoding uses COIN's output for both coins, so one state is saved. Timing diagram — two 20-cent coins, then "dispense":

The controller is the usual two-process VHDL FSM, with the CHG outputs assigned inside if gt0 = '1'.

Intuition

Decode first (a tree of states that each read one bit), then execute fixed sequences as chains of states, and use a single looping state with a datapath condition for anything of variable length.

Pitfall

Using to stop the change loop, as a careless design would, leaves 10 cents in the machine; testing in D1 instead of REQ would dispense after the credit has already started to fall. Write the timing diagram cycle by cycle before trusting the diagram: off-by-one errors between "commanded" and "visible" are the most common mistake.
