Signals versus variables

A signal assignment s < e= schedules a new value that becomes visible only after the process suspends (one delta cycle later); a variable assignment v : e= takes effect immediately and is local to the process; so inside one process run, reading a signal after assigning it still gives the old value.

Intuition

Signals behave like the outputs of flip-flops: all of them change together at the end of the step. Variables behave like scratch paper inside one computation.

Pitfall

Assigning a signal and testing it in the same process run (count < count + 1; if count = 9 then …=) tests the old value: the comparison is one cycle late.
