Pipeline hazards

In a five-stage pipeline (IF, ID, EX, MEM, WB) consecutive instructions overlap, so an instruction may need a result not yet written (data hazard), the next PC may be unknown (control hazard) or two stages may need the same unit (structural hazard); forwarding, stalls (bubbles) and branch prediction with flushing resolve them at some cost in CPI.

Definition

  • Structural: two instructions need one resource in the same cycle (a single memory for instructions and data). Fix: separate instruction and data memories, more ports.
  • Data (RAW): add x1,x2,x3 then sub x4,x1,x5: sub reads x1 in ID while add writes it in WB three cycles later. Forwarding sends the ALU result from the EX/MEM or MEM/WB register straight to the ALU input; a load-use hazard (lw x1 followed by use of x1) still needs one stall cycle, because the data appears only after MEM.
  • Control: the branch outcome is known in EX: the two instructions fetched after it may be wrong. Options: stall, predict not taken and flush on misprediction, dynamic prediction (branch history tables), compute the branch earlier in ID.

Intuition

Overlapping instructions is an assembly line; hazards are the moments when a worker needs a part the previous worker has not finished.

Pitfall

Forwarding paths add multiplexers to the ALU inputs, lengthening the critical path; deeper pipelines make branch mispredictions more expensive, so more stages are not always faster.
