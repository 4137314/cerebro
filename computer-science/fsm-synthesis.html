Method

  1. States: the creative step. A state is an abstraction of the input history — only what the future behaviour depends on (a button was pressed, not how many times; the start bit has arrived; the elevator is going up).
  2. State diagram: from every state, where each input combination leads and what the outputs are.
  3. Encoding: bits; it does not change the function, only the circuit (binary, Gray, one-hot; also chosen against races).
  4. Memory elements: D usually; T or JK through their excitation tables.
  5. State table: present state, inputs → next state, outputs; unused codes → don't-cares.
  6. Karnaugh maps for each flip-flop input and each output.
  7. Circuit, plus a reset to the initial state.

Speed: the next state must be stable at the flip-flop inputs before the next edge, so (1 GHz leaves the logic less than 1 ns). Too slow → setup violation: faster logic or slower clock (chips are binned by speed). Logic too fast between two flip-flops on the same edge → hold violation: add delay buffers; it cannot be fixed by the clock, the chip is scrap (setup and hold).

Example

Recognize 1101 on a serial input (one bit per cycle, overlaps allowed), in the cycle of the last 1 (Mealy). States: A nothing useful seen, B "1", C "11", D "110". Transitions (/): A: 0/0→A, 1/0→B. B: 0/0→A, 1/0→C. C: 1/0→C (still "11"), 0/0→D. D: 1/1→B (the final 1 starts a new sequence), 0/0→A. Gray encoding A=00, B=01, C=11, D=10, D flip-flops :

Intuition

The diagram is the program, the state register its program counter, the next-state logic a big lookup of "where do I go from here".

Pitfall

Forgetting arrows: every state must say what happens for every input combination (in a synchronous machine "nothing" means a self-loop, and it must be in the table). For overlapping recognition, from D on a 1 go to B, not to A — the last 1 may begin the next match.
