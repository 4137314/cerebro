Invariance of generics and wildcards

If B is a subtype of A, G<B> is not a subtype of G<A>, because a List<A> view would allow inserting an A into a list of B; wildcards recover flexibility: G<? extends A> is read-only covariant, G<? super A> write-only contravariant.

Derivation

Suppose List<Integer> were a subtype of List<Number>:

Erasure leaves no run-time check (unlike arrays), so the compiler must forbid the assignment. With List<? extends Number> reading gives a Number (safe) and adding is forbidden (the actual element type is unknown); with List<? super Integer> adding an Integer is safe and reading gives only Object.

Example

Intuition

PECS: Producer Extends, Consumer Super. If you only take things out, accept any subtype; if you only put things in, accept any supertype.

Pitfall

List<Object> is not "a list of anything": it does not accept a List<String>. The type that accepts every list is List<?>.
