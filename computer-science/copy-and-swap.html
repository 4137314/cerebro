The copy-and-swap idiom

Implement assignment as "take the argument by value, swap its contents with *this": the copy (or move) happens in the parameter, the swap cannot throw, and the old state dies with the parameter — one operator that is correct for self-assignment, gives the strong guarantee and serves both copy and move assignment.

Construction

Derivation

  • Self-assignment: a = a copies a into other, swaps, destroys the old copy: correct without a test.
  • Strong guarantee: the only operation that can throw is the copy into other, which happens before *this is touched.
  • Copy and move: if the argument is an lvalue, other is copy-constructed; if it is an rvalue, move-constructed. One function covers both assignments, so the rule of five reduces to four functions plus swap.

Intuition

Make a fresh, correct object first; then exchange contents with it and let the old contents be thrown away by a destructor that already works.

Pitfall

Copy-and-swap always builds a new object, even when reusing the existing buffer would be cheaper (assigning a vector to an equal-sized one): for performance-critical types a hand-written assignment can be faster, at the price of weaker guarantees.
