#+TITLE: cerebro

A personal, second-brain for mathematics: rigorous notes in English,
written in Org-mode/Org-roam, exported to LaTeX through a parametric
pipeline, in an environment isolated and pinned with GNU Guix. Meant to
last through a mathematics degree, a PhD, and an academic career after
that -- so everything here favours plain text, GNU tools, and things
that are easy to understand years from now over anything clever.

* Principles

- Plain text, versioned in git. No proprietary formats, no cloud
  services, no databases you can't read with a text editor. The
  "pattern-finding" query system (see below) is local, structural graph
  queries over your own notes -- deliberately not embeddings or a cloud
  service, which would break this principle.
- Isolation means Guix, not MELPA/straight.el at runtime. Every Emacs
  package, and now Taskwarrior/Timewarrior/jq too, comes from
  =guix.scm=; nothing is fetched from the network when Emacs starts.
- Reproducibility means a pinned Guix channel (=guix/channels.scm=),
  not just "uses Guix". Without a pin, the same commands can give you
  a different environment next year.
- Hooks are thin wrappers around =make= targets. The logic lives in
  the makefile, testable by hand; a hook only calls =make=. This is
  also the entire "CI/CD": local only, no forge dependency. Fast
  checks live in =pre-commit=; slower, graph-wide checks live in
  =pre-push=, not on the path of every commit.
- One Org source, many LaTeX/PDF variants -- never duplicated content.
  See "Parametric export" below.
- One source of truth per domain: notes live in Org/Org-roam, tasks
  and deadlines live in Taskwarrior, time lives in Timewarrior. The
  bridges between them are explicit, one-way scripts, not
  bidirectional sync.
- The tag taxonomy, export profiles, and LaTeX theorem environments
  are all *data* (an alist entry, a tag, a =#+NAME=) read by a handful
  of general mechanisms, not one bespoke code path per feature -- this
  is what "parametric" means here, and it's what keeps the whole thing
  KISS despite doing a lot.

* Bootstrap

Manual, one-time steps this repo cannot script for you:

1. Install Guix itself, if not already installed: follow the official
   manual's binary installation for a foreign distribution --
   https://guix.gnu.org/manual/en/html_node/Binary-Installation.html
2. After installing, run =guix pull= once, then regenerate the pin:
   =guix describe -f channels > guix/channels.scm= and commit it.
   Until you do this, =guix/channels.scm= is a template and
   =bin/guix-run= falls back to running unisolated with whatever is on
   PATH, with a loud warning (see the comments in that file) -- this is
   what let the very first commit to this repo happen before Guix was
   installed at all.
3. =direnv allow= in this directory. Note: =guix= itself is usually
   only on PATH in an interactive shell that sources
   =/etc/profile.d/guix.sh= (or equivalent) -- =bin/guix-run= also
   checks =~/.config/guix/current/bin= and =~/.guix-profile/bin=
   directly, so hooks and scripts work even from a shell that hasn't
   sourced that profile snippet.

Then:

- =make bootstrap-check= -- reports which prerequisites are present.
- =make shell= -- drop into the isolated environment interactively.
- =make install= -- installs the =cerbero= launcher (=~/.local/bin=),
  wires up the versioned git hooks (=git config core.hooksPath
  githooks=), and symlinks =taskwarrior/hooks/*= into =~/.task/hooks/=.

* Parametric export

: make export FILE=notes/example.org PROFILE=full
: make export FILE=notes/example.org PROFILE=statements
: make export FILE=notes/example.org PROFILE=lecture
: make export FILE=notes/example.org PROFILE=report
: make export FILE=notes/example.org PROFILE=manual
: make export FILE=notes/example.org PROFILE=slides
: make export FILE=notes/example.org PROFILE=single TARGET=thm-uniqueness-of-limits

One Org source, seven named outputs, composed from two independent
axes in =.emacs.d/lisp/cerebro-latex.el= (=cerebro-latex-content-modes=
x =cerebro-latex-doctypes= -> =cerebro-latex-profiles=): which blocks
survive (=full=/=statements=/=lecture=/=single=) and which class
typesets them (=article=/=report=/=manual= all via =latex/cerebro.cls=;
=beamer= via =latex/cerebro-beamer.cls= and Org's own ox-beamer
backend). Adding a new named preset is a one-line addition to that
alist, not new code -- see the file's own commentary for the exact
composition.

=single= extracts exactly one =#+NAME='d theorem-like block plus an
immediately following sibling =proof= block ("a focused sheet to
study"), discarding everything else in the file, by simple adjacency
-- not a dependency graph.

Notation (\R, \abs{}, \eps, TikZ/pgfplots/tikz-cd, cleveref, ...) lives
once in =latex/cerebro-macros.sty=, shared by every class.

Conventions for note authors, load-bearing for all of the above --
getting these wrong fails silently, not loudly (see the comments in
=notes/example.org= for the full list, worth reading once):
never set =#+LATEX_CLASS=/=#+LATEX_CLASS_OPTIONS=/=#+EXCLUDE_TAGS= in a
note file; write special block names lowercase; keep display equations
on one line starting with =\[=, not =|=; put meta-commentary in a
=#+begin_comment= block, not plain prose (a plain paragraph before the
first heading becomes its own slide in the =slides= profile).

* Tags

A small, controlled vocabulary (data in =org-tag-alist=, in
=.emacs.d/lisp/cerebro-org.el=), not free text: maturity
(=seed=/=growing=/=evergreen=), difficulty
(=easy=/=medium=/=hard=), epistemic status
(=conjecture=/=folklore=/=open_problem=), and an open-ended area group
(=analysis=, =algebra=, ...). See =notes/TAGS.org= for what each one
means -- the epistemic-status ones are structural, not just
descriptive: see "Consistency checks" below.

* Consistency checks

: make lint
: bin/cerebro-lint [file.org ...]

=bin/notes-lint.el=, wired into =githooks/pre-push= (not =pre-commit=
-- graph-wide checks don't belong on the fast path of every commit):
duplicate =#+NAME= labels (would silently break LaTeX compilation), a
=theorem=/=lemma=/=proposition=/=corollary= block with no adjacent
=proof= and no =conjecture=/=folklore=/=open_problem= tag on its
heading, headings using tags not in =notes/TAGS.org='s vocabulary, and
-- when the Org-roam database is available -- broken =id:= links and
orphaned nodes (reported, not an error: normal for a fresh =seed=
note).

* Query system

: make query Q=hubs
: make query Q=by-tag ARGS=evergreen

=.emacs.d/lisp/cerebro-query.el= (also =M-x cerebro-query-*=, =C-c q
...=), built on Org-roam's own =org-roam-db-query=: =orphans=, =hubs=
(ranked by backlink count -- your load-bearing concepts), =stale-hubs=
(a hub nobody has touched in a while -- foundational but neglected),
=co-citation= (two notes never linked to each other directly, but both
linked from many of the same third notes -- a structural pattern the
backlink view of either note, alone, won't show you), =by-tag=. Local
and structural on purpose, not embeddings or a cloud service.

* Issues

Personal, non-proprietary issue tracking: Org headings in
=issues/issues.org=, no external service. Create one with
=bin/cerebro-issue "title" [tag...]=, browse with =C-c i= inside
Emacs, or just edit the file directly.

* Taskwarrior / Timewarrior

Both are now part of the isolated Guix environment (=guix.scm=), along
with =jq= for the hooks below.

- =taskwarrior/hooks/on-add.cerebro=, =on-modify.cerebro=: tasks under
  the =academic= project (or any =academic.*= sub-project) get
  auto-tagged =cerebro= and a dated annotation, symlinked live via
  =make install-hooks=.
- =bin/task-to-org=: one-way bridge, =task +cerebro export= ->
  =agenda/taskwarrior.org= (gitignored, regenerated by =make ci= or by
  hand), included in =org-agenda-files=. One-way and regenerated from
  scratch on purpose, not a sync -- edit the task, not the generated
  file.
- =.emacs.d/lisp/cerebro-time.el=: =org-clock-in/out= mirrors into
  =timew start=/=timew stop=, so Timewarrior's own reporting sees
  cerebro time too.

* Testing

: make test

ERT tests (=tests/cerebro-latex-tests.el=, no Guix/Org-roam needed --
profile/doctype composition, the block-stripping and single-target
parse-tree filters, error handling) plus a POSIX-sh test script
(=tests/run-shell-tests.sh=, disposable temp dirs) for
=bin/cerebro-issue=, =bin/bootstrap-check=, =bin/guix-run='s fallback
path, and =bin/cerebro-new-book=. =make ci= runs this, then compiles
every named profile against =notes/example.org= as an integration
smoke test.

* Appearance

=.emacs.d/lisp/cerebro-appearance.el=: the built-in =modus-vivendi=
theme, no menu/tool/scroll bars, =hl-line-mode=, and Org's own
=org-pretty-entities= (renders math entities/sub/superscripts directly
in the buffer). No new Guix package, no heavy plugin -- everything
here has shipped in Emacs core since at least version 28.

* Status

The environment, Emacs config, the full parametric export pipeline (7
profiles, verified end to end against real LaTeX compiles), the tag
taxonomy, the consistency checker, the query system, real
Taskwarrior/Timewarrior integration, the test suite, and the appearance
tweaks are all wired up and working. What's still genuinely untested:
the Guix-side org-roam/task/timew/jq packages inside a from-scratch
=guix shell -f guix.scm= build on *this* machine takes a long time
(large `texlive-scheme-full` download) and may still be finishing in
the background; everything Guix-independent has been tested directly.
Not yet built: richer Org-roam capture templates (bibliography, more
theorem variants), and real usage-driven refinement of the Taskwarrior
hook policy -- both depend on how the workflow is actually used once
there is real coursework to take notes on.
